# CLAUDE.md

Guidance for Claude Code (and humans) working in this repo.

## What this is

**streamdeck-claude-plugin** is a Stream Deck plugin (UUID
`com.obalunenko.claudeperm`) that answers Claude Code from the deck: permission
requests (allow / always / deny) and `AskUserQuestion` prompts — several
questions with back / next navigation, single-choice and multi-select. When the
session's Terminal.app tab shows the prompt, a press is typed into that dialog
(arrows + Enter) so the terminal shows the deck's page; otherwise the hook
answers. A **Model / Effort** dial types `/model` or `/effort` into a running session's
Terminal.app tab. A **Usage** key or dial shows the context fill or a plan
limit (5h, 7d, the model-scoped weekly limit) as a green / yellow / red scale.

Claude Code hooks reach the plugin over HTTP on `127.0.0.1:47823`:

- `PermissionRequest` POSTs to `/permission` and long-polls; the response body is
  the hook's decision JSON.
- `PostToolUse`, `PostToolUseFailure`, `Stop`, `StopFailure`, `UserPromptSubmit`,
  `SessionEnd` POST to `/event` so the plugin can drop requests answered in the
  terminal and knows when a session's turn runs.
- The user's statusline POSTs its JSON to `/statusline` with the tty of its
  `claude` process in `X-Claude-TTY`: the dial's source of model, effort and tab,
  and the Usage meter's source of context fill and `rate_limits`.
- The user's statusline also writes `~/.claude/cache/oauth-usage.json` from the
  OAuth usage API; the plugin only reads it (5h, 7d, the scoped weekly limit).

The hook config lives in [`hooks.json`](hooks.json). Node 20 (the runtime Stream
Deck ships) · macOS · plain Stream Deck WebSocket protocol over `ws`, no Elgato SDK.

## Commands

```bash
make tools         # install the pinned Task from tools/task/go.mod (go install tool)
task --list        # all tasks
task deps          # npm ci
task test          # node --test: parsers, screen states, the Tuner
task build         # esbuild src/plugin.js → com.obalunenko.claudeperm.sdPlugin/bin/plugin.js
task icons         # render static icons from scripts/icons.sh (macOS sips)
task package       # build + dist/streamdeck-claude-plugin.streamDeckPlugin
task check         # tests + the Spec Kit update-checker tests
task speckit:install        # pinned Spec Kit + extensions (needs uv, Python 3.11+)
task speckit:update:check   # report newer Spec Kit / extension releases, install nothing
```

The `npm` scripts behind the tasks still work directly. Task itself is pinned
as a Go tool in `tools/task/go.mod` (Go 1.27); `make tools` installs every
`tools/*/go.mod`.

Spec Kit versions are pinned as `SPECKIT_*` vars in `Taskfile.yml` and passed
to the scripts as env. Extensions:
`companion`, `brownfield`, `bugfix` from their GitHub releases, and the local
`feature-numbering` from `.speckit/feature-numbering` (installed with `--dev`).

Install a local build by opening the package. Raise `Version` in
`manifest.json` first: Stream Deck skips a version that is not higher than the
installed one and never downgrades. Releases are `X.Y.Z.0` from the tag; local
builds raise only the fourth number, so the next release still installs over them.

## Hook behaviour (measured, not documented)

Measured on Claude Code 2.1.306; re-check after upgrades:

- The terminal dialog shows while the hook waits; the first answer wins, a late
  hook answer is ignored.
- **Yes** in the terminal does NOT cancel the hook — hence the `/event` cleanup.
  **No**, **Esc** and the hook timeout DO close the connection.
- `AskUserQuestion`: a bare `allow` does nothing. `allow` with `updatedInput` =
  the tool input plus `answers: {<question text>: <option label>}` answers it.
  A multi-select answer is the picked labels joined with `", "` in option order,
  as the terminal dialog sends it. The tool allows 2–4 options per question.
- Exit 2 is not honoured for `PermissionRequest`; deny through the decision
  object (`behavior: "deny"`, `interrupt`).

Model / Effort dial (fixtures in `test/fixtures/`):

- `model` / `effortLevel` in a settings file do not reach a running session;
  typing `/model <v>` / `/effort <v>` + Enter does, and the next statusline
  JSON shows it. `/effort` also saves the level as the model's default under
  `modelSettings` in `~/.claude/settings.json`.
- Terminal.app AppleScript: a tab has `tty`; `do script "<text>" in <tab>` types
  the text plus Enter into the program there, also in a background window,
  without raising it. `history` is the screen text. `busy` is always true while
  `claude` runs.
- The screen cannot tell a streaming reply from idle; a command typed then is
  queued. Busy comes from hooks: `UserPromptSubmit` → `Stop` / `StopFailure`.
  Esc fires no `Stop`; the screen shows `⎿  Interrupted` above the input box.
- A typed draft and Claude's grey suggestion look the same in `history`.
- Ctrl+S stashes a draft (or pops the stash into an empty prompt); the stash
  comes back after a submit. A held stash shows `› stashed` above the input box.
- `/model` mid-conversation asks to confirm (`❯ 1. Yes, switch to …`); a second
  Enter would confirm it. Dialogs replace the input box's `─── / ❯ / ───` frame.
  The confirmation shows within 1 s of the send (the dial's settle wait). After
  "No, go back" the draft stays stashed (`› stashed`).
- `/resume`, `/config`, the `/model` picker and Ctrl+R history replace the
  frame too, so the dial reads them as dialogs.
- A typed `/model` / `/effort` fires no `UserPromptSubmit`: it leaves no busy
  behind, and the next turn types.
- The statusline command's `$PPID` is `claude` itself (`ps -o tty=` prints
  `ttys006`); hook commands likewise. `ps -o comm=` follows argv[0]: `claude`
  when started from PATH, the full path (`…/claude`) when started by path.

`AskUserQuestion` dialog driven by `do script` (2.1.308, fixtures `test/fixtures/ask-*.txt`):

- Arrow escapes pass through `do script`; every send ends with Enter, and in
  this dialog Enter always acts. A page cannot change without answering, so the
  deck's Back and the dial do not move pages on the terminal path.
- A digit picks at once and moves on; the trailing Enter then acts on the next
  page. Only ↑ / ↓ runs are typed, with the Enter as the press.
- Single-select: Enter picks the highlighted option and moves on; the pick is
  not marked on its page (only ☒ in the tab bar and the review page show it).
  Multi-select: Enter toggles `[✔]` and stays; `Next` follows
  `Type something`; Enter there moves on, also with nothing checked. On the
  last page, and for a lone multi-select question, the button reads `Submit`
  and still only opens the review page, also with a question open.
- The highlight is wherever it was left (option 1 on a revisit, not the pick):
  read `❯` from the screen. ↑ on option 1 wraps (single-select: to
  `Chat about this`, which declines), so moves never wrap.
- Tab bar `←  ☐ Color  ☒ Snacks  ☐ Size  ✔ Submit  →` (current tab by colour
  only); one single-select question: ` ☐ Color `, footer `↑/↓ to navigate`,
  a pick submits at once; one multi-select question keeps the full bar. After
  the last page: `Review your answers` with `● q` / `→ a`, `⚠ You have not
  answered all questions` when one is open, `1. Submit answers` / `2. Cancel`.
- Long text from `do script` arrives as a paste (its Enter becomes a new line);
  five arrows plus Enter still arrive as keys.
- The hook connection and the dialog appear together; a terminal Submit or
  Cancel ends the hook's connection within 0.05 s.

Usage meter (measured on the user's machine):

- Statusline JSON: `context_window.used_percentage` (null early in a session),
  `rate_limits.{five_hour,seven_day}.{used_percentage,resets_at}` with
  `resets_at` in Unix seconds; absent for API-key logins. Each `claude` process
  reports its own copy; an idle one's can be from a window that already reset.
- `oauth-usage.json`: `five_hour` / `seven_day` `.utilization` and
  `limits[kind=weekly_scoped]` `.percent`, `.scope.model.display_name`, with ISO
  `resets_at`. The same reset arrives from both sources a fraction of a second
  apart.

## Conventions

- **Never send more than the key shows.** `Always` sends exactly the one
  suggestion it labels; never echo the whole `permission_suggestions` array.
- **Decisions come only from key presses.** The HTTP server has no endpoint
  that decides a request, and it rejects any request carrying an `Origin`
  header (browsers always send one; `curl` never does).
- **An empty 200 releases a request** without deciding it — Claude Code then
  falls back to its own dialog.
- **Profile switching** happens only when `Claude.streamDeckProfile` ships with
  the plugin; switching "back" without having switched would move the deck to
  an unexpected profile. Stream Deck imports a bundled profile on the first
  `switchToProfile`, behind a confirmation dialog in the app window.
- **Updates come from public GitHub releases.** The check is a plain `fetch`
  to the GitHub API, no token; a failed check is only logged.
- **Binaries by absolute path.** Stream Deck starts the plugin without the
  shell's PATH, so `claude`, `osascript` and `open` are found by absolute path.
- **Only the plugin's own values are typed.** `/model` / `/effort` with a value
  from `claude --help` or the dial's list, checked against `SAFE_VALUE`, passed
  to osascript as argv. Into a question dialog only ↑ / ↓ runs, and only while
  that tab's screen, read just before, shows this request's dialog on the
  deck's page.
- **Keep the plugin UUID.** The installed profile and the keys on the device are
  bound to it.
- **Comments and user-facing strings are in English.**

## CI / release

`.github/workflows/ci.yml`: the `package` job tests and builds the plugin on
every push and pull request and on `v*.*.*` tags. On a tag it sets the manifest
version from the tag, and the `release` job publishes a GitHub release with the
package attached. The release notes are generated by `scripts/release-notes.sh`
from the commit subjects since the previous tag (`docs:` / `chore:` / `test:`
commits left out), in the goreleaser changelog format.
